# 可灵（Kling）时长限制对分镜切割的影响

## 约束条件

- **可灵支持的时长**：整数秒 + 0.3秒增量（5.0s, 5.3s, 6.0s, 6.3s, 7.0s, 7.3s, ...）
- **取整行为**：向上取整（向上取整到最近的有效值）
- **最短时长**：5秒（小于5秒的镜头也至少生成5秒）

## 浪费分析

以一段 102 秒的旁白为例：

| 分镜数 | 平均每镜 | 可灵取整后 | 浪费比例 |
|--------|---------|-----------|---------|
| 15个 | ~6.8秒 | ~104.6秒 | **5%** ✅ |
| 60个 | ~1.7秒 | ~300秒 | **194%** ❌ |

**核心规律**：镜头越碎浪费越大。60个短镜会翻三倍时长和费用。

## 对 L05 分镜逻辑的建议

当前代码第967行的合并逻辑：
```python
max_shots = max(8, min(60, estimated_duration // 5))
```
对于 102 秒视频：`102 // 5 = 20`，上限20个。

这个逻辑有一个问题：它只考虑了"每5秒1个镜头"的粗略分法，没有考虑可灵向上取整导致的实际浪费。建议：

1. **合并后每镜尽量接近整数秒**（5.0, 6.0, 7.0...），减少0.3秒档的浪费
2. **长段（>10秒）强迫拆开**：10.37秒→11秒浪费0.63秒，拆成5+5.3浪费0.3秒
3. **短段（<5秒）必须合并**：3.67秒的段本身就要生成5秒，浪费1.33秒

## 触发条件

当以下情况时需要检查可灵浪费：
- 分镜数超过 `总秒数 / 4`（即平均每镜小于4秒）
- 合并逻辑跑完后，逐镜检查是否有大量<5秒的短镜
- 对DeepSeek输出尤其要留意（它容易分得碎，15镜左右还好，但千问之前出过60镜）

## 验证方法

```python
# 可灵有效时长列表
allowed = [5.0, 5.3, 6.0, 6.3, 7.0, 7.3, 8.0, 8.3, ...]

def calc_waste(shots):
    total_kling = sum(kling_ceil(s.duration) for s in shots)
    total_actual = sum(s.duration for s in shots)
    return (total_kling - total_actual) / total_actual * 100
```
