# 音频驱动数字人：让模型自己「演」

用于「开唱型」MV —— 一个人对着镜头唱，要气势、要表情、要口型全程对上。
与图生视频（I2V）的本质差别：I2V 是**端着首帧让它微动**，本路线是**模型根据音频 + 指令自己生成动作**。

## 一、可灵 Avatar（国内直连，优先试这条）

```
POST /v1/videos/avatar/image2video     # 提交
GET  /v1/videos/avatar/image2video/{task_id}   # 轮询
```

| 参数 | 要求 |
|---|---|
| `image` | 人像图 base64（**不带 `data:` 前缀**）。≤10MB，宽高均 ≥300px，宽高比 1:2.5–2.5:1 → 9:16 竖屏合法 |
| `sound_file` | 音频 base64，`.mp3/.wav/.m4a/.aac`，**≤5MB**，时长 **2–300 秒** |
| `prompt` | ≤2500 字符，**写动作 / 情绪 / 运镜**（这是本接口唯一能控表演的口子）|
| `mode` | `std`（720p）/ `pro`（1080p）|
| 输出时长 | **跟随音频**，不是固定 5/10 秒档 |

**计价：0.4 积分/秒（std）/ 0.8 积分/秒（pro）**。10 秒 ≈ 4 / 8 积分，比「i2v 10 秒（6）+ lip-sync」还便宜，且口型、头动、表情一次到位。

### prompt 怎么写（与 i2v 相反）

I2V 的唱镜要写「站定不动」，这里**恰恰要写满动作和情绪**：

```
他在激烈地唱歌：眉头压低，眼神死死盯着镜头不放，嘴唇有力地开合咬字，下颚发力，
头随着节奏前后小幅摆动，肩膀有力度地起伏。情绪越来越狠，脸部逐渐向镜头靠近。
镜头从胸口缓慢推进到脸部大特写，带轻微手持呼吸感。侧逆光勾边，脸上明暗对比强烈。
```

四类要素缺一不可：**情绪**（眉头/眼神/下颚）、**动作**（头/肩/前倾）、**运镜**（推近/手持感）、**光**（侧逆光/明暗对比）。

## 二、竖屏大特写首帧（决定成败的一半）

开唱型的脸必须够大，否则出来就是「中景里一个人在动嘴」。首帧规格：

- **9:16 竖屏**，如 864×1536 或 1080×1920
- **脸占画面高 60–70%**，从锁骨或胸口裁切
- 眼睛**直视镜头**，下巴微低，嘴闭合（口型从闭合起驱动）
- **单侧硬光**从画面一侧打，脸上出现明确的光影分割线；背景压到近黑 + 极浅景深
- 体态和服装沿用定妆图，用图生图（denoise 1.0 + 参考图）衍生，不要另起文生图

核验 prompt 模板：

```
Vertical 9:16 cinematic close-up portrait. Keep the face, bone structure, eyebrows, nose,
lips, jawline and hairstyle EXACTLY identical to the reference image. Face fills about 65%
of the frame height, cropped at the collarbone, looking straight into the lens, jaw clenched,
mouth CLOSED. HARD single side key light from camera left, strong light-to-shadow split down
the middle of the face, deep black background with a heavily blurred interior. 35mm grain.
No text, no watermark.
```

## 三、一条 10 秒验证片的标准做法

用户不想整片燒钱时，用这条最小验证：

1. 挑一句**慢句**（字速低、情绪重），从干声轨切 8–10 秒，≤5MB
2. 出一张竖屏大特写首帧，先过 vision 核：竖屏 / 脸占比 / 明暗分割 / 嘴闭 / 无畸形
3. 提交 Avatar（`mode: pro`，约 7 积分），等 3–5 分钟
4. 抽 1/2/3/4 秒四帧看：嘴在动、脸没崩、头有摆动、无背景干扰人

**成败判定**：如果四帧里能看到「表情随情绪变、头随节奏动」，就说明这条路能给用户要的「气势」，直接按它重做整首；如果只是「嘴在开合、人不动」，换 Vidu / Hedra / OmniHuman 再试一条。

### 已实测通过（拿它当基准，不要再绕 I2V）

竖屏 864×1536 首帧 + 8.84 秒干声 + `mode: pro`：

- 输出 **1072×1920 / 30fps / H.264 + AAC 44.1k 立体声**，8.6MB，耗时约 4–5 分钟，扣约 7 积分
- 抽 0/2/4/6/8 秒五帧：嘴角绷紧 → 皱眉开口 → 嘴张到最大咬字 → 双眼紧闭、面部肌肉全绷（气势顶点）→ 收尾换气
- 脸全程没崩、没换人，**镜头按 prompt 自己从胸口推到了大特写**

→ 结论：这就是「模型自己在演」，与 I2V 的「照片微动」是两个物种。同类需求直接按这个配方做。

**画布不是 1080×1920**：实际出片 1072×1920，拼装时 canvas 统一到 1072×1920（或整体 scale 到 1080），不要假设是标称值。

## 四、与其它音频驱动渠道的取舍

| 渠道 | 优势 | 代价 |
|---|---|---|
| **可灵 Avatar** | 国内直连、现有 key、按秒计费且便宜、prompt 可写运镜 | 单次跟随音频长度，长片仍需分段接 |
| OmniHuman（火山/即梦） | 长镜头能力强（最长 300s 一镜到底）| 三段流程（建角色→检测 mask→生成）+ 火山 AK/SK 鉴权 |
| Hedra / Vidu | 表情丰富 | 需梯子 / 另一套账号 |

长片拼法：按歌词段落切成 8–20 秒单元，每单元一个角度（正面 / 左侧 / 右侧 / 低角度仰拍）轮换，**低角度仰拍最出气势**；片段之间插 1 个空镜（塔吊、门口人群、桌面图纸）做呼吸，不要硬接。

## 五、语音时序注意

- 输出时长跟音频走，**不需要 tpad、不需要算帧号**，拼接比 lip-sync 链路简单
- 但**每段只能用它自己的音频起点**：换段落就要重新切音频 + 重跑，不能拿一段视频配另一段音频
- 背景若出现人群集体动作，可能被风控拒（与 lip-sync 同一个风控）；要人群就放到独立的空镜里
