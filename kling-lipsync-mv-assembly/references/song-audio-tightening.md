# 歌曲 MV 音频缩短（减前奏 / 压间隔）

用户说「前奏太长」「中间间隔压到三秒左右」时，交付的不是一段剪好的音频，而是**一整套重新对齐的工程文件**。剪错一处，后面全废。

## 0. 先量，再决定剪什么

拿到两条轨（整轨 + 纯人声）就先把结构量出来，别凭 SRT 首句猜前奏长度。

```python
import subprocess, numpy as np
def load(p, sr=16000):
    r = subprocess.run(["ffmpeg","-v","error","-i",p,"-f","f32le","-ac","1","-ar",str(sr),"-"],
                       capture_output=True)
    return np.frombuffer(r.stdout, dtype=np.float32)

vox = load("04_纯人声.wav")
hop = int(0.05*16000); n = len(vox)//hop
rv = np.sqrt((vox[:n*hop].reshape(n,hop)**2).mean(1))
voiced = rv > rv.mean()*0.12          # 阈值：整体 RMS 的 12%，太高会漏掉哼唱，太低会捞到噪声底
```

**必查三件事：**

1. **第一声在哪** —— 别假设它等于 SRT 第一句。实测有歌的第一句字幕在 14.20s，而纯人声轨 5.85s 就开始有内容（前奏里的无词人声/和声垫）。
2. **末尾有没有残响** —— 唱段结束后 RMS 若只剩 0.001–0.025，那是尾巴不是唱，不算「有人声」。
3. **连续静默 ≥1s 的位置清单** —— 这就是可用的切点候选。

同时算出**字速**（总字数 ÷ 唱段跨度）和**逐句字速**：

| 每字时长 | 24fps 帧数 | 对口型可用性 |
|---|---|---|
| ≥250ms | ≥6 帧 | 能真对上 |
| 208–250ms | 5–6 帧 | 跟得上节奏，别抠字 |
| <208ms | <5 帧 | 只能「大概」，构图要避开正脸特写 |

（同一首歌里最快句和最慢句能差 2.5 倍——按「平均字速」一刀切会误判。）

## 1. 只剪曲首

剪掉 `[0, P)`：新曲从原 `P` 起头，**没有拼接**，所以无爆音、无节拍错位、不需交叉淡化。

**切点 = 纯静默段起点**（不是随便一个小节线）。这样断字风险为零，剩下的 2–3 秒正好是器乐过门，第一句人声紧接进来，开场干净。

### BPM / 拍点要不要算

- **曲首截断不需要拍点对齐**：后续内容整体平移，节拍内部的相对关系完全不变，观众感知不到「曲首相位」的变化。别为了「落在小节线上」把切点挪到断字的位置。
- 只有在**中间拼接**（A 段 + B 段）时才必须对齐拍点／小节，而中间拼接本身就是高风险动作，能不做就不做。
- 自相关求 BPM 在说唱上常给出倍频歧义（实测同一条音轨最强峰 190.68，次峰 144.23，而实际记的是 143.6）。**不要拿自相关结果当硬结论**，更不要据此定切点。

## 2. 采样级精确切（两轨同一采样号）

```python
import numpy as np, soundfile as sf
CUT, FADE = 11.950, 0.015
def cut(src, dst):
    y, sr = sf.read(src, dtype="float32", always_2d=True)
    n0 = int(round(CUT*sr))              # 同一个 n0 给两条轨用
    z = y[n0:].copy()
    nf = int(round(FADE*sr))
    z[:nf] *= np.linspace(0,1,nf,dtype="float32")[:,None]
    sf.write(dst, z, sr, subtype="PCM_16")
    return len(z)
```

要点：

- **用 `soundfile` 按采样号切，不要用 `ffmpeg -ss` 处理 mp3 源**（mp3 有约 26ms 帧边界，两条轨会切出不同偏移）。wav 源用 `-ss` 也可以，但 `soundfile` 更直接、能保证两轨同点。
- 淡入 15ms 足够压掉起点跳变，不要更长（会吃掉第一拍的瞬态）。
- 输出 `PCM_16` 与原文件对齐；不要顺手重采样。

## 3. 衍生文件同步清单

| 文件 | 动作 | 自检 |
|---|---|---|
| 整轨 wav | 同 n0 截断 + 淡入 | 长度 = 原长 − P |
| 纯人声 wav | 同上 | **采样数与整轨完全相等** |
| SRT | 每句起止 − P | 句数不变，首句 = 原首句 − P |
| LRC | 每个 `[mm:ss.xx]` − P | 解码 → 正则替换 → **按原编码写回**（多为 GB18030），另出 UTF-8 版 |
| 干声切片 | 按新时间轴重切 | 每段时长 = 对应镜长 |
| 镜头表 JSON | 时间全部 − P，前奏镜合并 | 首尾无缝、每镜 ≤ 模型上限、末镜补 tpad |

LRC 正则（保留 `[ti:]/[ar:]/[by:]` 头，只动时间戳）：

```python
new = re.sub(r"\[(\d+):(\d+\.\d+)\]",
             lambda m: f"[{int((t:=int(m[1])*60+float(m[2])-CUT)//60):02d}:{t%60:05.2f}]", txt)
```

改名（如换歌名）也在这里一起做：`[ti:]` 改掉，**歌词正文不动**——先 grep 确认原歌名整句是否真在词里，多数情况下它只是标题，正文只有相近的句子（「换个方案加钱」「两套方案轮着扛」），那些是词，不能改。

c) **可视化核对**（回答「字幕会不会对不准」最有效的一招）：

- 降采样画波形（每段抽 1000–6000 点），纯人声与整轨叠两条
- 每句起点画一根竖线，行数按秒
- 分三屏画：开场 30 秒 / 段间一处 / 收尾一处。一张 166 秒的长图看不清细节

判据：每根竖线都应落在纯人声波形**刚开始起伏**的位置，不落在句子中间或静音里。

**不要用能量起音检测自证**：连续说唱句间无静音，包络抬升点乱飞（实测 47 句 −302 ~ +285ms），那是检测器无效。把它当「字幕不准」的证据会自己吓自己也误导用户。

## 5. 尾奏单独决策

尾奏常占 30–40 秒无人声，对抖音完播率是硬伤，但它是「留白」的设计位置。

**不要自己动手剪**，把秒数报出来并给建议（压到 12–15 秒、留 2 个空镜）让用户定——尾奏无词，剪它不影响字幕，风险低但也属于超范围改动。

## 6. 工具环境（本机）

音频分析要 `numpy/scipy/soundfile/matplotlib`，且本机 `PYTHONPATH` 会污染系统 python 的 PIL（matplotlib 导入报 `_imaging`）：

```bash
env -u PYTHONPATH -u VIRTUAL_ENV /usr/bin/python3.10 script.py
```

`execute_code` 沙箱里没有 numpy，音频类计算一律走 `terminal` + 上面这个解释器。没有 librosa，用 scipy 做包络/自相关就够。
