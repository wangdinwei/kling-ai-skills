# 可灵对口型做 MV：分段 → 拼接 → 烧字幕

## When to Use

- 有整首歌 + 已生成的一批无声人物视频，要做「人物跟着歌对口型」的 MV。
- 需要判断对口型偏移、决定哪里切、哪里垫定格、怎么补长窗口。

**现成脚本**：`scripts/assemble_frame_exact.py` —— 帧精确拼接（改顶部 SEGS/SONG 即可跑，先 `--list` 核帧级时间轴，`--rough` 带占位块试跑）。
**开工前先量脸**：`scripts/face_size_audit.py` —— 逐镜输出「脸高占画面高」，用来决定哪些镜值得跑对口型。
**模型选型**：`references/model-landscape.md` —— 可灵 / Seedance / OmniHuman 各自适合什么，以及行业里四种对口型路线。
**写故事**：`templates/narrative-mv-story-treatment.md` —— 叙事型 MV 故事脚本骨架（循环式核心句 + 四个母题物件首尾呼应 + 五幕分工 + 自检清单），复制改就能用。

## 入口闸门 0：先定路线 —— 「叙事型 MV」还是「开唱型 MV」

用户一句「做出来的不生动，抖音上火的是脸贴得很近、唱歌对口型、有气势」就等于宣告**路线错了**，不是平台错了。两条路线工具、画幅、景别、镜头数、光影全都不同：

| | 叙事型 MV | 开唱型（怼脸唱） |
|---|---|---|
| 谁在演 | 模型**端着首帧让它动**（I2V/T2V）| 模型**按音频自己演**（音频驱动数字人）|
| 画幅 | 横屏 16:9 | **竖屏 9:16** |
| 景别 | 中景/过肩/空镜，脸占 15–25% | 舞台型：大特写 60%+；**生活化 live 型：半身 25–35%**（见下「两个亚型」）|
| 对口型 | 只有 2–3 个近景值得花钱做 | **全程都对**，因为驱动源就是音频 |
| 镜头数 | 12–26 镜 | 4–6 个大特写角度轮换 + 3–4 个空镜呼吸 |
| 光影 | 环境光（顶灯+窗光）| 舞台型：单侧硬光劈明暗、背景压黑；**生活化 live 型：侧逆光勾边 + 正面柔补，背景必须有信息量** |

### 开唱型有两个亚型——别默认按「大特写 + 黑底」拍

| | 舞台/演唱会展播型 | **生活化 live 型（本用户的口味）** |
|---|---|---|
| 场景 | 舞台、桁架、观众灯海、头戴麦 | **真实生活场景**：乡间土路、便利店、办公室、酒店房、夜市饭桌、车里 |
| 景别 | 大特写，脸 60%+ | **半身 25–35%**，人和环境同框 |
| 光 | 单侧硬光劈明暗，背景近黑 | **侧逆光勾边（发丝光）+ 正面柔补**，暖 3200–3600K，背景有信息量 |
| 参考 | 演唱会电视转播多机位 | @乡野低频（录音棚老者）、@石红豆（碎花年代感女子）那一类 |

**实测教训**：先按「黑底 + 单侧硬光 + 脸占 60%」出的四张风格图，被一句「不要搞这种邋里邋遢的人像，要清爽、有个性」否掉。两个原因：
1. **景别错**：他要的是「一个人在他生活的地方自然地唱」，不是棚拍怼脸。背景空掉就只剩一张脸，没有故事。
2. **造型错**：沧桑/风霜形象只能做一次性情绪爆款；要长期更新的数字人系列，**造型必须清爽、干净、有个性**（干净的形象才能接商单、跨场景、被反复看不腻）。

→ 做系列时把这两个亚型当成**两套独立影调**，不要混：舞台型靠光和气氛，生活化型靠**场景的具体物 + 侧逆光 + 空气里的介质**。（场景/空镜提示词的写法在 libtv 技能的 `references/15_场景提示词写法.md`。）

**I2V 的先天天花板**：首帧锁死了构图、光影、场景，模型只能让它微动；写进 prompt 的运镜常不执行，情绪也演不出来。用它做叙事型 MV 没问题，**用它做开唱型一定失败**——用户说的「直接约束了场景颜色，不生动」就是这件事。

**开唱型的正解**：`references/audio-driven-avatar.md` —— 一张竖屏大特写 + 一段干声，让模型自己生成头部摆动、表情、口型、镜头推进。可灵自带这条接口（`/v1/videos/avatar/image2video`），用现有 key、国内直连、比 lip-sync 链路简单。

**这位用户说「MV」＝默认「开唱型」。** 他没强调画面叙事时，要的是全程有人对着镜头唱。别拿平台播放量去反推路线：实测 B 站同类高播放作品里，740 万那支是纯文字排版（均镜长 41.6 秒、全片零角色）、137 万那支是静态插画 + 硬字幕，两者都没人真开口唱；但「氛围型 + 字幕 + 静帧推拉」的方案拿给他，照样被一句「MV 的方向还是不对，我喜欢演唱的」否掉。**播放量说明的是平台生态，不是他要的东西**——拿数据去论证氛围型，是路线判断错误，不是数据错误。

做「固定几个电子人、持续唱不同歌」的系列时同理：**开唱型是唯一能立住人设的形态**（同一张脸、同一副嗓子、每支都怼脸唱），叙事型/氛围型立不起来「像明星」这件事。

**一句话判断**：这首歌的高潮是「一个人对着镜头唱」还是「一场戏」？前者走音频驱动，后者走 I2V 叙事。路线定错，后面每个环节都白做。

## ⚠️ 入口闸门：先量脸占比，再决定花不花这个钱

**这是本类任务最贵的一条教训。** 对口型只有「看得见」才算数：脸在画面里越小，花在 lip-sync 上的钱越是白花。开工前用 `scripts/face_size_audit.py` 逐镜量一遍，按结果分配预算：

| 脸高 / 画面高 | 处置 |
|---|---|
| ≥ 25% | **只有这类才值得跑对口型**（近景特写）|
| 14–22% | 别跑。能看到嘴动、看不清字形，观众不会觉得「对上了」|
| < 15% | **绝对不跑**，直接用原片；嘴小到本来就看不见 |

实测一部 15 镜的 MV：只有 4 镜脸 ≥25%（60%/59%/37%/31%），7 镜 14–22%，3 镜 10–12%。即 **11/15 的钱花在了看不见的地方**——用户反馈「从来没对上过」，真相不是模型失效，是构图错配。

**字速上限（物理约束，先算再承诺）**：说唱约 5.75 字/秒 → 每字 ~174ms；视频 24fps 每帧 41.7ms → **每个字只有约 4 帧**。这个量级下任何模型都只能「大概」，不要向用户承诺逐字精确。慢速抒情段落才是对口型的适用区。

**镜头设计铁律**：运镜失败时，**不要**把全片提示词统一改成 `the camera holds static`。实测后果是整片变成一串不动的说话镜头，观感就是「讲课」。正确做法是分摊：一部分镜头靠光影变化与主体动作承载动态，只把真正推不动的镜头做固定机位，并靠**剪辑节奏（镜长 2–5s）**而不是运镜来救。

## 构图：图生视频锁死构图，文生视频才有镜头语言

| | 图生视频（I2V）| 文生视频（T2V）|
|---|---|---|
| 谁定构图 | **首帧定死**，文字只能控“怎么动” | 模型自己构图、自己调度 |
| 运镜指令 | “缓慢推进/拉远”经常不执行（与“保持首帧”矛盾）| 能执行跟随、变焦 |
| 人物一致性 | 好（同一首帧）| **差，每镜一张脸** |

**成片「构图差」多半不是提示词差，是首帧那张图差**（正面居中/平光/全身/同一种景别）。I2V 的任务就是“端着这帧让它动”，要求它改构图是逆着设计用。

**混合策略（省钱且绕开一致性短板）**：

| 镜头 | 用什么 |
|---|---|
| 背影 / 剪影 / 逆光 / 空镜 / 物件 / 手 / 鞋 / 杯 | **T2V** —— 构图自由，且脸不一致也无人追究 |
| 需要看清脸的近景、要口型 | **I2V**（固定一张定妆照）+ 对口型 |

### 几十张首帧图要「从定妆图衍生」，不是每镜独立文生图

I2V 的一致性上限由首帧决定，所以**首帧本身必须是同一张脸**。每镜各跑一次文生图 = 脸漂 N 次，下游再怎么锁都救不回来。

正确顺序：定妆图（正面 / 45° / 侧脸，同一角色三张）→ 逐镜改构图与场景（图生图 denoise 0.5–0.65，或多图参考编辑）→ 得到 N 张「同一张脸、不同机位」的首帧。两张参考一起用效果最好：`image1`=定妆图锁脸，`image2`=构图草稿锁姿势机位，提示词写「脸照 image1 完全一致，姿势/构图/服装/光线照 image2 不要改」。

首帧 prompt 与视频 prompt 要分开存（`first_prompt` / `prompt` 两个字段）：首帧是**静态瞬间**且必须 `mouth firmly closed`（口型从闭嘴起驱动），视频 prompt 才是动作与运镜。

一致性靠一段**人物块**原样贴进每条 T2V 提示词：
`RECURRING SUBJECT: Chinese man, 40, short black hair greying at temples, thick brows, tired eyes, stubble, navy suit worn at the cuffs, white shirt untucked, frayed employee badge on a lanyard.`

背景人群一律写 `motion-blurred silhouettes / backlit / no discernible faces`；写“几百人同时转头/举杯”必崩。

可灵 T2V 端点：`POST /v1/videos/text2video`，参数同 I2V 但用 `aspect_ratio`（`16:9`/`9:16`），`duration` 仍只认 `"5"/"10"`。

**T2V 实测输出**：1280×720 / 24fps，`mode: std`。第一条测试镜头（低角度地铁楼梯跟拍）就拿到了真实机位移动 + 人物进出画 + 背景人群自动变成运动模糊剪影，无畸形、无扭曲人脸。**「运镜在图生视频里不执行、在文生视频里执行」这一点已实测确认**——所以构图与运镜问题先换 T2V，不要先怀疑提示词。

**故事先写死，再拆镜头**：一次性把整段故事丢给模型，它只会从里面挑一个画面并反复生成同一种构图。正确顺序是先写故事骨架（为什么这么拍），再拆 12–20 个 5–10 秒镜头（拍什么）。骨架可直接复制 `templates/narrative-mv-story-treatment.md`（含「循环式核心句 + 四个母题物件首尾呼应 + 五幕分工 + 自检清单」）。

## 叙事型 MV：多数 MV 根本不对口型

对口型是“演唱型 MV”的惯例，不是硬要求。叙事型 MV 靠**物件 + 背影 + 光线 + 城市空镜**承载情绪，全片只需 1 个清晰正脸镜头。

规划顺序：先写**故事骨架**（为什么这么拍）→ 再拆 12–20 个 5–10 秒镜头（拍什么）→ 选 3–4 个**贯穿物件**替代情绪词（工牌/冰美式/闹钟/地铁扶手）→ 最后才决定哪几镜值得对口型（先量脸占比）。

**没有口型约束时，切点是自由的**：不必卡在音节起点，可以按叙事节奏挪 ±1.3s 而完全无感。素材长度与歌词窗口对不齐时，优先挪切点而不是加定格；只有当某段素材明显短于窗口才用 `tpad`。

**素材段数 ≠ 时间轴段数**：N 段素材通常要排 N±1 段。多出来的素材可放在**相隔 ≥20 秒**处复用（作主题回收），少的那一段由更短的镜头切分补上。

**用户反馈“花了几千块从来没对上口型”时，先不要答应换模型**：先量脸占比、再算字速上限、再做二值检验。很多时候对口型本身是生效的，只是做在看不见的地方。

## 双人对唱 / Battle：唱句归属按歌词判定，不照抄用户的段落指令

用户给的往往是按时间粗分（「A 唱 0:05–1:08，B 唱 1:08–1:59」）。但歌词里有**身份指认句**，能直接推翻这个分配：

- 找 2–3 句「只有某一方能说」的锚点句。例：「**你**偏要当**我**的甲方」只能由被骂的那方（总包）说；「你也只敢冲我横，催款电话一个不敢挂」只有甲方说才通
- 锚点句所在段落，说话人就被定死了；剩下的段落按「谁被指认、谁在辩解」推

**处置**：按歌词内容排，**在方案里写清为什么对调**，同时给出「一条命令翻回来」的切换法（对调 singer 标签 + 对调首帧图即可；干声切片不用动——切片是按时间切的，与谁唱无关）。这比闷头执行错分配、或直接顶回去都好。

**递进结构优先判给同一人**：若副歌/尾段出现「刚才骂你的每一句我自己全都对得上」这类自我反噬句，说明前面可能是同一人的两面——这时双人可保留（观感更好），但最后一段要轮流认账，别让一个人一路骂到底。

### 同框「一唱一听」做不到：只能交替剪辑或分屏

用户要的是「左边那个在唱、右边那个闭嘴听，只靠眼神冷笑在反应」。**没有任何通用视频接口能可靠做到这件事**：实测可灵 I2V 把「ONLY 左边的人张嘴 / 右边全程闭嘴」写进 prompt、负面词写 `both mouths moving, mouth open on the right man`、`cfg_scale` 压到 0.25，抽 0/2/4 秒仍**两人同时张嘴**，出来是「两人对吵」。数字人接口更直接：**它只驱动一个主体**。

两条可行路：

| 做法 | 怎么干 | 代价 |
|---|---|---|
| **交替剪辑**（首选）| 双人同框镜只用来交代关系（两人都动嘴无所谓）；要「一唱一听」就切**单人怼脸**：唱的人走 Avatar，听的人单独出一个反应镜（冷笑/摇头/抿嘴/翻白眼）| 镜头数变多，但每镜都好控 |
| **分屏假同框** | 左半屏「A 单人 3/4 侧脸朝右」用干声走 Avatar 真唱；右半屏「B 单人 3/4 侧脸朝左」用**静音轨**走 Avatar（嘴自然不动，只剩眼神眉毛）；后期左右拼一屏 | 每 10 秒约 16 积分（两人各 8）；两张图必须**同光源方向 + 同背景色温 + 同景别高度**，否则拼起来一眼假 |

**双人首帧里别塞背景人群**：模型会自作主张给观众加戏（一个个张嘴震惊），成片一眼假。要人群就单独出一个空镜。

## 拼接阶段四个坑（全部实测踩过）

| 坑 | 现象 | 处置 |
|---|---|---|
| **单次 `filter_complex` + concat 静默丢帧** | 计划 4514 帧，输出只 4447（少 67 帧，: 2.2s） | 改**分段 `-frames:v N` 精确编码 → concat demuxer 无损拼接 → 合音频**，每段帧数逐位可核 |
| **`-shortest` 会截掉音频尾巴** | 实测截掉 200 采样（4.5ms） | 去掉 `-shortest`，让画面比音频长一帧，音频完整保留 |
| **逐段 `-t` 累加取整误差** | 23 段 × ±1 帧 → 总时长偏 +0.1s | 边界先按秒定义，再 `round(t*30)` 转帧号，**段长 = 相邻帧号差** |
| **SRT 带 UTF-8 BOM** | 首句序号变成 `\ufeff1`，`isdigit()` 失败 → 首句把时间码当字幕烧进画面 | 读取时 `.replace('\ufeff','')`；另注意 CRLF |
| **素材比需求少 1 帧** | 10.042s × 30fps = 301.26 帧 → 要 302 帧的段编码后只有 301，全片少 2 帧 | 该段加 `tpad=stop_mode=clone:stop_duration=0.04` 补 1 帧；`-frames:v N` 出来后再 `-count_frames` 逐段核 |

**音频是否真没动的验证方法**（不要只比对文件 MD5，mp3 进 mp4 会因容器 padding 对不上）：

```python
# 解码成 PCM 后逐采样比
# 1) 找最佳偏移（应为 0 采样）2) 对齐后最大差值应为 0、相同采样占比 100%
```
实测交付片：偏移 0 采样、最大差 0、相同占比 100.0000%，仅末尾多 859 采样容器填充。

## 长镜头缺口的正确填法（避免“怪物”）

| 手段 | 用在哪 |
|---|---|
| 句末切，把缺口压短 | 所有镜 |
| `tpad=stop_mode=clone` 定格 ≤0.3s | 句间过门 |
| **静帧推镜（zoompan）** | 1–5s 缺口；静帧无嘴型，不存在对口型问题 |
| **重新生成一个新机位** | >5s 的缺口 |
| 原素材不跑口型直接用 | 主角脸占画面 <15% 高的广角（嘴部本来就看不清）|

## 音频默认不动；用户要「缩短」时只剪曲首，不中间拼接

**默认沿用「音频不动」**：原曲整条 `-c:a copy` 复用，不裁剪、不重编码、不变速。时间轴零点与原曲起点有毫秒级差时，**在片头垫黑场**（`color=black:d=0.02`）对齐，不要去裁音频——`-ss 0.02 -c:a copy` 会在 mp3 帧边界（约 26ms）上切出静默偏移。交付前断言音轨 codec 与原格式一致。

**但用户会要求「减前奏 / 中间间隔压到 3 秒左右」**（MV 要紧凑、要完播率）。这时不要拒绝，按下面的安全剪法做，并**把全部衍生文件一起重算**——剪了音频不改字幕/干声/镜头表，交付的是一堆互相错位的废件。

### 只剪曲首＝纯截断，是唯一零风险剪法

剪掉 `[0, P)` 后新曲从原 `P` 处起头：**不存在 A+B 拼接**，所以无爆音、不需交叉淡化，节拍内部关系也不变（只是曲首相位变了，观众感知不到）。

- 切点选在**纯人声轨静默段的起点**（连续静默 ≥1s 的位置）：既不断字，又天然留出器乐铺垫
- 采样级精确切：`soundfile` 读 wav → 按**采样号**切片 → 15ms 线性淡入 → 写回 PCM_16。**两条轨必须切在同一个采样号**，否则口型用的干声和成片用的整轨会错位
- 平移量精确等于剪掉的采样数；后面所有时间戳整体减这个量，误差为 0 且不累积（无重采样、无变速）

### 中间间隔不要硬压

先量再答：句间间隔往往本来就在 3 秒内。更何况段落之间纯人声覆盖率常是 100%（拖长音、和声没停），硬剪等于把一个字从中间切开，还破拍点。**把实测数据摆出来（如 3.17 / 1.33 / 2.45 秒）说明已达标**，比照着指令硬剪更专业。

### 一次剪完，六类文件同步重算

| 文件 | 动作 |
|---|---|
| 整轨 wav | 同采样号截断 + 淡入 |
| 纯人声/干声 wav | 同上（**同一采样号**）|
| SRT | 每句起止 −P |
| LRC | 每个时间戳 −P；另出 UTF-8 版（原文件常是 GB18030）|
| 干声切片 | 按新时间重切（`ffmpeg -ss -t`）|
| 镜头表 | 时间全部 −P，前奏镜合并，末镜补 `tpad` |

### 交付前三件验证（缺一不可）

1. 两轨新长度**采样数完全相等**
2. 两轨互相关最佳 lag = **0 采样**
3. **波形 + 字幕竖线可视化**逐句核（做法见「字幕」一节）

完整配方（切点选择、BPM/拍点要不要算、脚本骨架、反向验收）见 `references/song-audio-tightening.md`。

```bash
# 不要加 -shortest：它会按较短流收尾，实测截掉音频末尾 4.5ms
```

## 唱镜的 i2v prompt：动作写多了，人会走出画面

**首帧是静止的「人在吵架」，写成动作就会失控。** 实测两镜（都是 10 秒档）：

| 写了什么 | 实际出来 |
|---|---|
| `leaning in over the desk, jaw clenched, eyes narrowed` | 他**自己转身到桌边低头看图纸**，最后镜头变成侧脸特写 —— 口型对得像在看东西 |
| `Side view of the two men facing each other` | 0–6 秒两人还在，**第 9 秒其中一人走出画面**，只剩一个 |

根因：I2V 的职责是「端着首帧让它动」，写进情绪动词（lean / turn / lift / step）模型会当成调度指令去执行，人一走动就出画，而唱镜一旦出画，后面的 lip-sync 花了钱也没意义。

**规则：唱镜 prompt 只写「站原地 + 面对面 + 开口说话」，不写位移类动作。**

```
… stands exactly where he is, facing the other man, mouth moving as he speaks, head barely shifting.
The two men stay exactly where they are and keep facing each other for the whole shot.
```

负面词必须写死：`turning away, turning back, walking away, leaving frame, stepping out of frame, looking down at the desk, body moving, approaching the camera`。

想表现「拍桌 / 接电话 / 摘帽子」这类动作，**不要靠 i2v 演**——把它做成首帧的静态状态（帽子已经在桌上、手机已经贴在耳边），或者单独给一个新的非唱镜。

**验收靠抽帧不靠单帧**：每镜抽 0/3/6/9 秒四帧并排看。四帧要「在动」，但**主要人物必须始终在画面里、始终朝着对方**。只有单帧好看、连起来人不见了的镜，一律重做。

## 主体库（element）锁人：接口、格式、机位取舍

**用户说「主角要锁住」时，只有一条官方路：先建可复用主体，再在每次生成里引用它。文字描述锁不住脸，也锁不住「人别走出画面」。**

创建（**不计费**，可放心建多个）：

```
POST /v1/general/advanced-custom-elements
{"element_name": "owner_40_suit",                                   // ≤20 字符
 "element_description": "40岁中国甲方业主，深灰西装敞着无领带，不戴安全帽",  // ≤100 字符
 "reference_type": "image_refer",
 "element_image_list": {
   "frontal_image": "<base64 或 URL>",                              // 必须 1 张正脸
   "refer_images": [{"image_url": "<45°>"}, {"image_url": "<侧脸>"}]}}   // 1–3 张不同角度
```

图片限制：jpg/png、单张 ≤10MB、短边 ≥300px、宽高比 1:2.5–2.5:1（1344×768 的三角度定妆图正好过）。
轮询 `GET /v1/general/advanced-custom-elements/{task_id}`，取 `task_result.elements[0].element_id`。

引用时**必须是对象，不是裸 ID**：

```json
"element_list": [{"element_id": 325171257673128}]   // ✅
"element_list": [325171257673128]                    // ❌ 400 element_list[0] value type is invalid, expected object
```

- 文档把 element 挂在 omni 名下，但 **`kling-v3` 的 `/v1/videos/image2video` 实测接受 `element_list`**，提交即通过
- 格式错会被 400 直接拒、**不扣积分**，所以格式没把握时先拿单镜试，不要一次推全片
- 最多 3 个主体；**与 `voice_list` 互斥**
- 主体建好后是「一次创建、多次引用」，换项目才需要重建

### 一致性 vs 机位多样性：对白镜必须收敛到少数机位

每多一个新机位 = 多一次 i2i 重绘 = 场景细节被重新编造一遍。26 镜铺 14 个机位，用户一眼就会说「每一镜好像看起来都不一样」（他的原话）。

**取舍原则（用户拍板采纳 A 方案）：**

| 镜头类型 | 机位 | 为什么 |
|---|---|---|
| **承载对白的镜**（15–20 个）| 只用 **4 个**：正面全景 / 过肩看 A / 过肩看 B / 侧面双人 | 观众要看脸和口型，一致性优先；4 次重绘差异压得住 |
| 过门 + 情绪镜（句间 1–3 秒）| 用特色机位：桌面细节 / 人群反应 / 逆光剪影 / 俯拍 / 门口往里 | 不承载关键台词，细节差异记不住，反而提供呼吸感与多样性 |

- 相邻两镜机位不要相同
- 4 个对白机位之间靠**裁切比例 + 取景高度**（center / top / low）出景别变化，不需要新图
- 别用「每句一镜」凑机位：全曲常有一批不足 1 秒的短句，可灵最短 5 秒档，一句一镜等于花 3 积分生成 5 秒再裁到 0.5 秒，口型也没意义。**按句末切、一镜 2–6 句**

## 硬事实（全部实测，不是文档抄的）

| 项 | 实测值 |
|---|---|
| 接口 | `POST /v1/videos/lip-sync`，`model_name: kling-v3` |
| 视频输入 | **`video_id`（不是 task_id）**，取自图生视频结果的 `videos[0].id` |
| 音频输入 | base64，`audio_type: file` |
| 单次时长上限 | **10 秒**，必须按镜头切音频喂 |
| 是否要歌词文本 | **不要**。纯音频波形驱动 |
| 返回 | **自带音轨**（aac 128k），1264×720，比输入短约 0.075s |
| 耗时 | **约 170 秒/段**，不是秒级 |
| 断点续跑 | 必须落盘 lip_id，中断后按 id 轮询即可 |
| **计价（kling-v3 std 720P 无原生音频）** | **0.6 积分/秒** → 5s = 3 积分、10s = 6 积分；**lip-sync 0.5 积分/5 秒** |
| 全片预算示例 | 26 镜（7×5s + 19×10s = 225 秒）= **135 积分**，17 段口型约 110 秒 = **11 积分**，合计 **146** |

**报价前先对官方价目，不要用「pro + 原生音频」那一档估。** 同一部片按 std 无声算是 146 积分，按 pro 有声算是 380+，差 2.6 倍——报高了会让用户以为做不起，报低了会中途断粮。我们自己喂干声，`sound` 一直是 off，永远走最便宜那档。

**v3-omni 的 `voice_list` 不是「喂干声」**（最容易误用的一条，照抄第三方模板必踩）：

| 你以为 | 实际 |
|---|---|
| `voice_list: 一段干声文件/URL` 驱动口型 | `voice_list` 是**定制音色 ID 列表**（基于主体库音色），根本不吃音频文件 |
| `element_list` + `voice_list` 一起写 | **两者互斥，不能共存**，同时出现直接报错 |
| `element_list: ["甲方工程师"]` | 要填**主体库 element ID**，不是名字；建高级主体还需 1 张正面 + 1–3 张同人参考图 |
| `freedom: 0.2` / `motion_has_audio: true` | 官方没有这两个参数名。一致性用 `cfg_scale`（0–1，越低越贴提示词）；是否生成原生音频用 `sound: on/off` |
| `model_name: kling-v3-omni-video-generation` | 未必是这个写法，名字以官方文档为准，**先拿一个 5 秒测试镜验模型名**，不要拿全片赌 |

→ **要用歌曲干声驱动口型，只有 `/v1/videos/lip-sync` 一条路**（`video_id` + `audio_file`）。omni 的原生音频是模型自己生成的音色/语音，跟你的干声无关。
→ duration：`kling-v3` 只认 `"5"/"10"`；`kling-v3-omni` 支持 3–15s。第三方模板里的 `00:05–01:08` 这种一分钟长镜不可能成立，必须拆。
→ 用户拿一份现成 JSON 模板来（多来自别的平台/教程），**先逐字段对一遍官方口径再照做**，比提交后被拒一轮省事得多。

**时间映射关键结论**：输出的 9.967s 是**掐掉尾巴**，不是压缩。
用互相关在 7 个采样点（0.2/2/4/6/8/9.3/9.7s）比对，偏移**恒定 −0.020s、零漂移**。
→ 推论：**每段只能放在它自己的音频起点上**，不能挪位、不能 setpts 拉伸；跨段也不会累计漂移。

## 它会自己分辨“有没有人在唱”（实测）

同一 video_id 喂两种音频：

| 喂什么 | 结果 |
|---|---|
| 纯人声 | 嘴明显张合，与语音节奏一致 |
| **纯伴奏**（demucs no_vocals） | **嘴基本不动**，只眼睛眉毛微变 |

→ 不必先分离人声，原曲切片直接喂即可（人声在混音里占主导）；
→ 段内没人唱的空档它自动闭嘴，**不需要人工对齐谁唱谁不唱**。

## 验证对口型是否真的生效（二值检验，比互相关可靠）

不要用互相关（见下文否决记录）。用**无唱段做二值检验**：

1. 从 SRT 里挑一段**明确没有唱**的空档（过门/间奏），换算成该镜头内的时间点
2. 从 lip-sync 输出里抽两组帧：有唱区 3 帧 + 无唱区 3 帧
3. 有唱区嘴应张开/形变，无唱区嘴应闭合

实测（近景，脸占 60%）：有唱 2s/4s/6s 嘴张开呈 O 型 → 无唱 7s/7.8s/8.4s **完全闭合**。一次抽帧就能判定「音频驱动真的在生效」。

**这条只证明「驱动生效」，不证明逐字准确**。逐字准确取决于脸占比与字速，两者不够就别承诺。用户质疑「从来没对上过」时，先量脸占比，再跑这条检验，用数据分清是模型问题还是构图问题。

## 拼接规则（对齐口型 + 对齐歌词 + 去冗余）

1. **切点必须落在 SRT 句末或句间空档**，不能切在字中间。先把 SRT 解析成毫秒级句子表，再选切点。

   ⚠️ **但「SRT 句间空档」不等于「没人唱」**：长音拖尾与和声会让这些空档的纯人声覆盖率仍是 100%（实测 3.17s、2.45s 两处皆如此）。这些位置**不能安排「人物闭嘴的近景」**——嘴上没动、音轨有声，一眼假。改用**物件特写 / 围观者反应 / 双人远景**承接（脸小，嘴看不清）。真正的纯静默段要自己量（连续静默 ≥1s），量法见 `references/song-audio-tightening.md`。
2. **窗口 < 9.97s**：直接裁尾，冗余丢掉。
3. **窗口 > 9.97s**：**不要用同一 video_id 再跑一次对口型**（相邻两段同素材＝硬跳接，见下文「禁止」一节）。按「长镜头缺口的正确填法」处理：先句末切压短缺口，再定格／静帧推镜／新机位。
4. **零头（<0.3s）**：`tpad=stop_mode=clone:stop_duration=X` 定格在句间过门，看不出来。
5. 拼接时**视频只用画面（-an）**，最后合原曲母版音轨——避免各段 AAC 接缝处电平跳变和段内几十毫秒偏移叠加。
6. 统一 `scale/crop/1248x720` 附近原始尺寸、`fps=30`、`setsar=1` 后再 concat。

## ⚠️ 走不通的路：逐帧嘴型 × 音频包络互相关（已否决）

**诱人的想法**：算嘴部 ROI 的帧间运动能量，和音频 onset 包络做互相关，求滞后帧数。

**实测结论：不成立，不要用。**
标定方法：同一段视频换上已知平移的音频（0 / +100 / +200 / −100 ms），看检测器报什么：

| 真实平移 | 检测器报出 |
|---|---|
| 0 ms | −4 帧 |
| +100 ms | −1 帧 |
| +200 ms | +2 帧 |
| −100 ms | −5 帧 |

峰值突出度只有 1.1–1.4，相关峰 0.14–0.20。**完全跟不上真实平移。**
原因：说唱类音频起音密集（~5 次/秒），画面运动里混着头部晃动和镜头运动，互相关退化成噪声。

**纪律：任何自动对齐检测器，先用「已知平移标定」验收；跟不上就废弃，不许拿它下结论。**

## ✅ 正确标定法：脉冲法（已测过，延迟 = 0）

要测「模型内部的音画固定延迟」，用脉冲而不是找相关：

1. 造 10s 静音，只在**第 5.000 秒**塞一个真实唱音节（从人声轨切 0.55s，`volume=2.0`）
2. 喂 lip-sync，下载输出
3. 扫嘴部 ROI 帧间运动，找嘴“动起来”的那一帧
4. 该帧时间 − 5.000s = 模型固定延迟；再用第 3.000 秒做第二个脉冲验证一致性

**实测结果（kling-v3，两次独立脉冲）：延迟 = 0.000s（0 帧）。**
- 5.000s 脉冲 → 4.97:0.00 → **5.00:7.39** → 5.07:6.10 → 5.13:6.24
- 3.000s 脉冲 → 2.97:0.00 → **3.00:14.17** → 3.07:6.48 → 3.13:6.08

→ **不需要任何全局平移。** 加上音频侧互相关恒定 −0.020s，两条独立证据确认 1:1 对齐。

**另一个必须知道的实测细节**：喂静音时，**片段开头 0–2.9 秒仍有较高嘴部运动能量**（两段一致，均值 4.4–7.8），因为模型保留了原视频自身的动作。所以「静音自动闭嘴」只对中后段成立，**不要指望片段开头会闭嘴**，需要靠切点避开。

## ⚠️ 禁止：相邻段复用同一素材重配口型

长窗口（>9.97s）如果拿同一 video_id 再跑一次对口型，两段连在一起就是**硬跳接**：上一段已演到第 9 秒，下一段从第 0 帧重来，嘴还对着不同歌词 —— 一眼看出是错的（审片人会叫它“怪物”）。

正确处理优先级：
1. **先在句末切**，把缺口压到最短
2. 缺口 ≤0.3s → 定格垫进过门
3. 缺口较大 → **补一个新镜头（换机位/换角度）重新生成 5s 或 10s**，比硬跳接便宜得多
4. 非要复用同一素材，只能用在**相隔 ≥20 秒的远处**（当作主题回收），不能相邻

- 恒定 → 只是掐尾，1:1 可用
- 线性增长 → 被压缩过，必须逐段 setpts 校正

## 字幕

**先确认字幕源的权威性，再动手烧。** 用户常常同时给 SRT 和 LRC：

| 文件 | 怎么判断 | 处理 |
|---|---|---|
| LRC 带 `[ti:]`/`[ar:]`/`[by:]` 头 | **这是官方歌词文件**（词曲作者署名在里面）| 可作权威文本 |
| 无标签的 SRT | 常是同一份歌词转出来的，文本应当一致 | 当时间轴来源，文本与 LRC 交叉核对 |
| LRC 乱码 | 多为 GB18030 | `iconv -f GB18030 -t UTF-8` 后再用；行尾是 `\r\n` |

**用户说「字幕文字是错的 / 你是不是用 Whisper 重听了」时：先举证，不要道歉也不要重做。** 做三源对照，一次定性：

1. 解析 SRT → `(起, 止, 文本)` 列表；解析成片用的 ASS → 同结构；逐句比时间差与文本
2. 从**已交付的成片**里抽 6–13 个时间点裁出字幕条，读回来与 SRT 原文比对
3. 把用户指认的「错别字」丢回**他自己的 LRC/SRT** 里 grep

实测经验：三源往往完全一致，被指认的「错别字」本来就在用户的源文件里（气口、咽音常被写成「啊听」这类）。此时如实说「片子里的字就是你文件里的字，一字未改」并给出对照表，再问「这两处是原词还是想改」，不要自作主张改词。

**画布变了必须重算字幕规格**：ASS 的 `PlayResX/PlayResY` 必须等于成片画布，否则 libass 会按比例缩放导致字号与边距错位（1268×724 → 1280×720 也要重生成，不能直接复用旧 ASS）。

- 字号按画布高的 8–12% 取（720 高 → 79–80px），描边约字号的 5%（4px），`MarginV` 约画布高 9%（65）
- 主色纯白、描边纯黑、`Shadow 0`、`WrapStyle 0` 智能换行；MV 不要投影，容易糊
- 母版码率 ≥4 Mbps，别用 crf 定画质

**「字幕会不会对不准」要能一次答死。** 剪过音频或改过时间轴之后用户必问这条，而且他自己也能听出来。

- **不要用能量起音检测自证**：连续说唱句间没有静音，包络抬升点会乱飞（实测 47 句偏移 −302 ~ +285ms，只有 17 句落在 ±120ms 内）。那是检测器无效，**不是字幕不准**。拿这个当结论既吓自己又误导用户。
- 可靠的答复是两条硬证据 + 一张图：
  1. **机制**：采样级硬截断 N 采样 = X.XXXXXX 秒，无重采样、无变速、无中间拼接 → 平移量精确且不累积
  2. **同源**：两轨互相关 lag = 0 采样
  3. **可视化**：把新音频降采样画波形（抽 1000–6000 点即可），每句起点画一根竖线，看竖线是否都落在人声刚开始起伏处；三处关键段各画一屏（开场 / 段间 / 收尾）比一张全长图好看清

**字幕位置验收**：抽帧时必须带 `-copyts`（`-ss` 放在 `-i` 前会重置时间戳，测出来的「字幕错位」是命令用法造成的假象）。

## 图生视频被风控拦（lip-sync 报 risk control）

**症状**：`task_status: failed`、`task_status_msg: Failure to pass the risk control system`，同一条 video 反复重提都失败 —— **是确定性的，不是偶发，别猜是网络或帧率**（同一批视频 fps 完全相同，仍只有某一条失败）。

**一次调用定因（画面还是音频）**：把一条**已知跑通过**的音频（别的镜头上成功过的切片）喂给这条 video：

| 结果 | 结论 |
|---|---|
| 仍失败 | **画面内容**被风控，与音频无关 |
| 成功 | 音频问题（极少见） |

**处置优先级**：
1. **脸占画面高 <15% 的广角，直接不跑口型用原片** —— 嘴本来就看不清，零成本
2. 换机位重新生成，提示词去掉易触发元素（人群集体动作、天花板破开这类灾难／集会观感）
3. 不要反复重提

## 钱闸门：图和方案定稿后，必须拿到明确同意才开机

**这是用户自己定的规则，不是建议**：图没定、方案没定，一镜都不许提交；图和方案定稿后，还要等一句明确的「开机」。

实测踩过：用户回了一句「好的」，我当成开机信号直接提了 3 镜测试（约 15 积分已扣），随即被叫停并明确要求「得到同意才可令开机」。

**判定信号要严格**：

| 用户说什么 | 能不能提交 |
|---|---|
| 「好的」/「行」/「知道了」 | **不能**，那是在回应你上一条的说明 |
| 「开机」/「开始跑」/「推吧」/「可以跑全量了」 | 能 |
| 要你先跑测试镜，你提出来他同意了 | 能，但只跑你提的那几镜 |

**已经提交了怎么办**：不要偷偷杀掉——积分已经扣了，杀掉等于钱和结果一起丢。如实说明「已提交 N 镜、积分已扣、脚本只处理这几镜不会再往下跑」，然后停下来等指令。

### 开工前先查真实余量，不要相信口述或上次估算

```
GET https://api-beijing.klingai.com/account/costs?start_time=<ms>&end_time=<ms>
Authorization: Bearer <JWT>
```

返回 `resource_pack_subscribe_infos[]`，逐包看 `remaining_quantity` / `status` / `invalid_time`：**只有 `status: online` 的包能用**，`expired`（过期）与 `runOut`（用完）都不算钱。`start_time` 要往前放宽一年，否则历史包查不到。

**积分按包分别消耗，过期包里的余量看着是钱、其实归零**：实测「试用-视频-1000」剩 552.8 已过期、「试用-图像-10000」剩 9284 已过期，真正可用的只剩正式包 116.15。

**纪律**：任何「还能不能做完整片 / 够不够跑」的结论，只认这个接口里 online 包之和；用户口述的额度、自己上次的估算都会偏（实测口述 319、此前估 147，实际可用 116）。

## 交付与汇报（用户对交付形态有明确偏好）

这位用户看片靠「一眼判断」，不看长文分析。交付时固定三件套，正文只写 3–5 行摘要：

1. **成片**（先压到 <25MB 走飞书文件接口，读回确认 `msg_type=file`；母版另存服务器并给绝对路径）
2. **12 帧缩略图拼版**（`ffmpeg` 拼 4×3，这是他真正会看的那张图）
3. **规格表**：分辨率 / 帧率 / 帧数 / 时长 / 码率

**明确不要**：把逐镜的提示词、论证过程、踩坑清单全铺在消息里——他会直接说「像讲课」「听听就想睡觉」。踩坑只挑 3–4 条最有画面的讲，其余留在技能与 OB 里。

## 抽卡的前提是「只留一个变量」（用户一句话点破的最硬教训）

用户原话：「每次做出来的东西都完全不一样，这种观念差别很大，怎么抽嘛？」——他说得对。

抽卡能收敛，是因为先锁死了四样：**影调（摄影机+镜头+颗粒+LUT）、角色资产、场景资产、首尾帧**。变量只剩「运动自然不自然」。
每次从一段文字重新生成、构图光线人脸全自由发挥 → **那不是抽卡，是每次买一张随机图**，钱花在废片上。

**纪律：没锁变量就别抽；要抽就先锁死上面四样，并只抽「同一条锁定的运动好不好」。**

## 剪辑必须按音乐小节，不按歌词句子

这是「剪得散」的根因——按歌词句子切，片子就失去音乐性。

1. 先锁歌 → 检 BPM（Suno/成片都不显示，用 librosa 或剪辑软件）
2. 导入音频，**每个重拍打一个标记，建拍点网格**（剪映/达芬奇可自动识别节拍；Premiere 跟底鼓按 M）
3. 分镜 8–10 个，每镜时长 = **1 / 2 / 4 小节**，绝不 1.5 小节
4. 生成档位只有 5/10 秒 → **多生成一档，再裁到切点吸附重拍**
5. 逐帧确认每个切点都落在重拍上

> 眼睛会原谅踩在拍上的丑剪辑，永远不会原谅脱拍的漂亮剪辑。

## 「AI 味」主要来自影调没写全

AI 默认输出是「过度数字化的清亮感」，缺胶片颗粒、暗角、镜头畸变这些真实物理痕迹。只写 `cinematic realism` 太笼统。影调模板要写全六个维度：

```
Shot in the visual style of [参考片], captured with ARRI Alexa 35 and Cooke anamorphic
lenses producing oval bokeh, heavy 35mm film grain, slight vignette, organic skin tones,
f/1.4 shallow depth of field, graded toward [冷白+薄荷青] — no digital cleanliness.
```

维度：色彩倾向 / 摄像机型号 / 镜头型号 / 胶片颗粒 / 光圈景深 / 暗角畸变 / 参考片名。

## 成本结构与验证方式（用户已为此花掉上万）

行业实测：**AI 短片后期占 80–90%**，生成只占一成多；一条 3 分钟片子至少要 36–60 个片段；一分多钟的纯 AI 广告片光后期做两周。所谓「一键出片」不存在。

**验证永远用 15 秒，不用整片**：同一段副歌 + 影调锁死 + 角色锁死 + 只抽运动 + 抽 3 条全给用户挑。整片验证一次 ¥100–200，失败了用户只会说「烂」，且不知道烂在哪。

**向用户汇报时必须分级，不要含糊**：
- 能搞定的：锁变量、拍点网格、抽运动、调色统一、音效层、帧精确拼接
- **搞不定的**：选哪条最好看。模型能给指标（无瞳形/曝光正常），给不了眼光。MV 的上限正好在这一层。

## ⚠️ 七个实际踩过的硬门槛（2026-10 新片实测）

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | **lip-sync 拒“脸太小”** | 17 段里 11 段报 `The model detected a face that is too small`，失败不扣分 | 硬门槛：脸占画面高 <15% 的镜根本跑不了。**开工前先量脸，别等提交完才知道** |
| 2 | **element_list 格式** | 裸 ID 数组 `[123]` 报 400 `element_list[0] value type is invalid, expected object` | 必须写 `[{"element_id": 123}]`。**创建主体（custom-elements）不计费**，先用定妆图 1 正面 + 1–3 参考图建成 element，后面每镜带上 |
| 3 | **不写“站定不动”人真的会走出画面** | 同一镜旧版 9s 时主角完全出画；新版四帧都在 | 两道同时上：prompt 末尾加 `the men stay rooted where they are and keep facing each other, only mouths and heads move, nobody turns away, nobody walks out of frame` + 负面词加“转身/走开/走出画面/背对镜头/低头看东西”。**不要靠压 `cfg_scale` 治出画（见下条）** |
| 4 | **WAV 不能 copy 进 mp4** | `Could not find tag for codec pcm_s16le`，产出 0 字节文件 | PCM 源必须转 `-c:a aac -b:a 320k`（“音频不动”指不裁不变速，不是不转容器编码） |
| 5 | **i2v 与 lip 共用 progress 同名段位** | lip 阶段全部打印“已存在，跳过”，实际一段没跑 | 两个阶段用不同段位名：i2v 存 `file`，lip 存 `lip_file` / `lip_task_id` |
| 6 | **编辑模型“提质感”会砍锐度** | qwen_image_edit 渲染后拉普拉斯方差 **848 → 222（-74%）**，高频能量 133 → 79 | 编辑模型的“更真实”是柔化+颗粒换来的。要质感就在**成片阶段**加轻锐化和细颗粒，不要在首帧上过编辑模型 |
| 7 | **多机位 = 多次重绘 = 一致性崩** | 14 个机位各重绘一次，用户一眼看出“每一镜都不一样” | 分层：**有台词的镜只用 4 个机位**（正面全景/过肩×2/侧面双人），过门镜才用特色机位（桌面/人群/逆光/俯拍）；或彻底单机位换绝对一致 |

### ⚠️ 不要用压 `cfg_scale` 来治「人走出画面」—— 那会把动作一起压死

「`cfg_scale` 越低越贴提示词」这句话容易让人拿它去防出画，实测代价很大：

| cfg_scale | 出画 | 动作 | 评分 |
|---|---|---|---|
| **0.3** | 不出 | **人物几乎不动、背景完全静止**，像一张定格照 | 5/10 |
| **0.7** | 5 秒镜实测四镜均未出画 | 抬手、转身、躯干扭转、尘埃飘动 | **9/10** |

低 cfg 所谓的「稳」，是把运动幅度一并压掉了 —— 而「动」正是走这条路唯一值钱的东西。**正确分工：**

1. **出画用 prompt + 负面词管**（`stay rooted`, 不能 `turning away / walking away / stepping out of frame`）
2. **动作幅度用 cfg 管，默认 0.7**，需要更激烈再往上试
3. **长镜容易出画就缩短单镜** —— 实测 5 秒档 + cfg 0.7 没出画；之前出画的是 9–10 秒长镜。用「多切几镜」而不是「压 cfg」解决

这条与本地模型同一个机理：**判一个参数调得对不对，只看一个指标——画面里除了嘴，还有别的地方在动吗？**

**正面案例**：同一张 1792×1024 底板 + i2i 低重绘推 14 个机位，再 26 镜全部从这 14 张裁切（只降采样不放大，锐度 629–848），场景和人物就是同一批人。锐度校验：`ffmpeg` 抽灰度帧 → 拉普拉斯方差 + FFT 高频占比 + 8×8 块局部对比度。

## 常见坑

- `video_id ≠ task_id`，把 task_id 填进 lip-sync 会报参数错
- 单次 >10s 音频会被拒或截断
- 下载易 `ContentTooShortError`，用 `curl -sL --retry 3` 重下，`urllib.urlretrieve` 不稳
- 后台批处理用 `-u` 无缓冲运行 + 落盘 progress.json，否则超时后无从续跑
- 飞书预览会丢音轨：先验音频独立存在，另发一份 mp3 对照
